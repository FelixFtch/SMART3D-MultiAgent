\begin{abstract}

We present a multi-agent navigation system for unknown environments built on the \smarttd{} incremental replanning framework. Existing sampling-based planners assume fully known maps; grid-based multi-agent path finding (MAPF) methods assume known graphs and discrete movement. Our system removes both assumptions. Each agent carries a simulated LiDAR sensor, discovers walls incrementally, and repairs its RRT* tree in place rather than rebuilding from scratch. A shared wall discovery mechanism propagates newly found walls across all agents, enabling cooperative map exploration. Deadlock resolution uses a priority-based reactive coordination layer (Global King with flee, chain push, and multi-direction retreat) that operates in continuous space without modifying the planning trees. We validate the system across 8 procedurally generated scenarios (32m to 192m) with up to 8 agents and 30 dynamic pedestrians. In 50{,}000+ benchmark trials, the full system achieves 100\% success rate on all large-scale maps with 4 agents. Shared wall discovery yields $1.04\times$--$2.09\times$ speedup over independent exploration. Incremental repair reduces navigation time by $22.4\times$ compared to full tree rebuilding on the largest maps. The system has been deployed on a physical robot (Raspberry Pi~5 + Alienware i9 central planner) navigating real indoor environments via ROS2 and CycloneDDS.

\end{abstract}

\section{Introduction}

Multi-robot navigation in unknown environments is a prerequisite for applications ranging from warehouse logistics to search-and-rescue. The problem requires three capabilities simultaneously: (1) planning collision-free paths with incomplete map information, (2) updating plans as new obstacles are discovered, and (3) coordinating multiple agents to avoid deadlocks.

Existing approaches address subsets of this problem. Grid-based Multi-Agent Path Finding (MAPF) methods such as CBS~\cite{sharon2015cbs} and PIBT~\cite{okumura2022pibt} find optimal or near-optimal solutions for hundreds of agents, but assume fully known grid maps and discrete, synchronized timesteps. Sampling-based planners like RRT*~\cite{karaman2011sampling} operate in continuous space and handle complex geometry, but most variants assume static, known environments and plan for a single robot. Reactive methods like ORCA~\cite{berg2011reciprocal} handle dynamic obstacles in continuous space but lack global planning and fail in narrow corridors where local velocity adjustments cannot resolve conflicts.

\smarttd{}~\cite{agrawal2025smart3d} introduced an incremental tree repair mechanism for single-robot navigation around dynamic obstacles in known environments. When a moving obstacle intersects the planned path, \smarttd{} prunes affected edges, searches for hot-nodes (tree nodes with neighbors in different disconnected subtrees), and reconnects the tree locally. This repair takes $\sim$5\,ms versus $\sim$40\,ms for a full RRT* rebuild, enabling real-time obstacle avoidance.

We extend \smarttd{} along three axes:

\begin{enumerate}
    \item \textbf{Unknown environments.} We introduce \texttt{update\_static\_obstacles()}, which applies the prune-and-reconnect mechanism to permanently discovered walls. The original algorithm only handles transient dynamic obstacles; our extension handles walls that, once discovered, never disappear. This requires a different tree management strategy: pruned nodes are permanently discarded rather than restored when the obstacle leaves.

    \item \textbf{Multi-agent shared wall discovery.} When agent $A$ discovers a wall via LiDAR, all other agents' trees are immediately updated. This cooperative exploration yields $1.04\times$--$2.09\times$ faster completion compared to independent discovery, validated over 12{,}000 trials.

    \item \textbf{Reactive coordination in continuous space.} A Global King priority system with active flee, chain push, and multi-direction retreat resolves deadlocks without modifying any agent's planning tree. The coordination layer operates purely at the execution level, decoupled from the sampling-based planner.
\end{enumerate}

We validate the complete system across 8 procedurally generated scenarios ranging from 32m buildings to 192m university campuses, with up to 8 agents and 30 dynamic pedestrians. The system achieves 100\% success rate on all large-scale maps (1{,}000 trials each), and has been deployed on a physical robot using ROS2 with a central planner architecture.

\section{Related Work}

\subsection{Multi-Agent Path Finding (MAPF)}

Conflict-Based Search (CBS)~\cite{sharon2015cbs} finds optimal solutions by branching on pairwise conflicts, but computation time grows exponentially with agent count in narrow corridors due to pairwise path symmetry~\cite{li2019symmetry}. Suboptimal methods scale better: Priority Inheritance with Backtracking (PIBT)~\cite{okumura2022pibt} handles thousands of agents on grids via dynamic priority transfer, and LaCAM~\cite{okumura2023lacam} achieves similar scale with lazy constraint addition. However, all grid-based MAPF methods share two assumptions that limit real-world applicability: the map is fully known before planning, and agents move in discrete timesteps on a graph.

H\"onig et al.~\cite{honig2019persistent} demonstrated that both assumptions break down in real warehouse deployments, where asynchronous execution and continuous dynamics require replanning. Lifelong MAPF~\cite{ecai2024lifelong} addresses the persistent task stream but still requires a known graph.

\subsection{Sampling-Based Replanning}

Several algorithms extend RRT* to dynamic environments. DRRT~\cite{ferguson2006replanning} invalidates affected edges and regrows the tree. RRTX~\cite{otte2016rrtx} propagates cost changes globally. ERRT~\cite{bruce2002real} biases new samples toward the previous tree. These methods operate in continuous space but require global tree modifications or resampling after each environment change.

\smarttd{}~\cite{agrawal2025smart3d} takes a different approach: it prunes only edges within a local Critical Pruning Region (CPR) and reconnects via hot-nodes, preserving the majority of the tree structure. A single repair takes $\sim$5\,ms on 15{,}000-node trees. However, the original work assumes all static obstacles are known a priori and plans for a single robot.

Our work extends \smarttd{} to unknown environments with multiple cooperating agents. Unlike DRRT and RRTX, we preserve the local repair property of \smarttd{} while adding wall discovery and multi-agent coordination.

\subsection{Reactive Multi-Robot Coordination}

ORCA~\cite{berg2011reciprocal} computes collision-free velocity constraints between agent pairs. It works well in open spaces but fails in narrow corridors where the velocity obstacle set has no feasible solution, leading to permanent deadlock. DWA~\cite{fox1997dwa} has similar limitations.

Our coordination mechanism draws inspiration from PIBT's priority inheritance but operates in continuous space rather than on a grid. The key difference: PIBT agents backtrack by one grid cell; our agents flee along computed directions in continuous coordinates, with the planning tree providing fallback global paths.

\section{Problem Formulation}

Consider $N$ agents operating in a 2D workspace $\mathcal{W} \subset \mathbb{R}^2$ containing static walls $\mathcal{O}_{\text{static}}$ and $M$ dynamic pedestrians $\mathcal{O}_{\text{dyn}}$. Each agent $i$ has:
\begin{itemize}
    \item Position $\mathbf{p}_i \in \mathcal{W}$, radius $r_i$, speed $v_i$
    \item Goal position $\mathbf{g}_i \in \mathcal{W}$
    \item A LiDAR sensor with range $R_s$ that returns intersection points with walls within line-of-sight
    \item A local map $\hat{\mathcal{O}}_i \subseteq \mathcal{O}_{\text{static}}$ of walls discovered so far
\end{itemize}

At time $t=0$, $\hat{\mathcal{O}}_i = \emptyset$ for all agents. As agent $i$ moves, its LiDAR reveals walls within range $R_s$, updating $\hat{\mathcal{O}}_i$. Each agent maintains an RRT* tree $\mathcal{T}_i$ built against its current known walls.

\textbf{Objective.} Navigate all $N$ agents to their respective goals $\{\mathbf{g}_i\}$ while:
\begin{enumerate}
    \item Avoiding all static walls (known and unknown)
    \item Avoiding dynamic pedestrians
    \item Avoiding inter-agent collisions
    \item Minimizing total navigation time $\max_i t_i^{\text{arrive}}$
\end{enumerate}

\textbf{Shared discovery.} In cooperative mode, when agent $i$ discovers a new wall $w$, it is immediately added to all agents' maps: $\hat{\mathcal{O}}_j \leftarrow \hat{\mathcal{O}}_j \cup \{w\}$ for all $j$. This models a centralized planner with shared sensor data, which matches our deployment architecture (Section~\ref{sec:deployment}).

\subsection{Phase 1: LiDAR Scan and Wall Discovery}

Each agent casts 180 rays uniformly over $360\degree$ with range $R_s$. Each ray is tested against all walls in $\mathcal{O}_{\text{static}}$ (ground truth); the closest intersection within $R_s$ is returned. Walls behind other walls are occluded. Newly discovered walls are merged into the global known wall set.

In shared mode, a single discovery triggers tree repair on \emph{all} agents. In independent mode (ablation baseline), each agent only updates its own map.

\subsection{Phase 2: Incremental Wall Repair}
\label{sec:wall_repair}

When new walls are discovered, we must update each agent's RRT* tree. We implement three strategies with increasing efficiency:

\textbf{Full Rebuild (baseline).} Discard the entire tree and run RRT* from scratch with all currently known walls. Cost: $O(K \log K)$ where $K$ is the number of RRT* iterations (5{,}000--160{,}000 depending on map size). This guarantees a clean tree but takes 40--500\,ms and produces a completely new path with no continuity guarantee.

\textbf{Eager Incremental (E3).} Apply \texttt{update\_static\_obstacles()}: scan all $E$ edges in the tree, prune those intersecting the new wall, then reconnect via hot-node search. Cost: $O(E)$ per new wall, typically $\sim$5\,ms on 15{,}000-node trees. The tree structure is preserved except for pruned edges, maintaining path continuity.

\textbf{Lazy + Eager (recommended).} If the new wall does not intersect the current path, only swap the validity checker without scanning the tree (lazy). If the wall blocks the current path, fall back to eager repair. This reduces unnecessary computation when walls are discovered in irrelevant regions.

Algorithm~\ref{alg:wall_repair} describes the eager repair procedure.

\begin{algorithm}[t]
\caption{Incremental Wall Repair (\texttt{update\_static\_obstacles})}
\label{alg:wall_repair}
\begin{algorithmic}[1]
\REQUIRE Tree $\mathcal{T}$, new wall $w$, validity checker $\mathcal{V}$
\STATE $\mathcal{V} \leftarrow \mathcal{V} \cup \{w\}$ \COMMENT{Update checker with new wall}
\STATE $\mathcal{E}_{\text{bad}} \leftarrow \{e \in \mathcal{T} \mid e \text{ intersects } w\}$ \COMMENT{Scan all edges}
\FOR{each $e \in \mathcal{E}_{\text{bad}}$}
    \STATE Prune $e$ from $\mathcal{T}$ \COMMENT{Tree fragments into subtrees}
\ENDFOR
\STATE $\mathcal{H} \leftarrow$ \textsc{HotNodeSearch}($\mathcal{T}$, $R_{\text{LSR}}$)
\FOR{each hot-node $h \in \mathcal{H}$ ranked by utility}
    \STATE Attempt reconnection through $h$
    \IF{reconnection valid under $\mathcal{V}$}
        \STATE Rewiring cascade to update costs
    \ENDIF
\ENDFOR
\STATE \textbf{return} \textsc{BuildPath}($\mathcal{T}$)
\end{algorithmic}
\end{algorithm}

\textbf{Detour detection.} Over successive repairs, path quality may degrade. We monitor the ratio $\rho = \|\text{path}\| / \|\mathbf{p}_i - \mathbf{g}_i\|$. If $\rho > 1.5$, a full rebuild is triggered to restore path optimality.

\textbf{E3 vs.\ path-only repair.} An alternative strategy (``Senior'') scans only edges adjacent to the current path, ignoring the rest of the tree. This leaves ``dirty edges'' (edges crossing discovered walls) in unexplored tree regions. When an agent is later forced to use those regions (e.g., pushed by another agent), it encounters invalid edges and must perform a full rebuild. In multi-agent settings with shared wall discovery, dirty edges accumulate rapidly because walls discovered by remote agents may affect tree regions far from the current path. Our benchmarks show that E3 (full-tree scan) triggers $4$--$9\times$ fewer rebuilds than path-only repair, resulting in 18--23\% faster median navigation time on large maps despite higher per-repair CPU cost.

\subsection{Phase 3: Dynamic Obstacle Avoidance}

Each agent uses \smarttd{}'s native \texttt{SMART::update()} for dynamic pedestrians. The original algorithm is unchanged: compute Obstacle Hazard Zones (OHZ) based on pedestrian speed, prune edges within the Local Reaction Zone (LRZ), and reconnect via hot-nodes. The King agent (Section~\ref{sec:king}) plans as if other agents do not exist; non-King agents treat all other agents as dynamic obstacles with OHZ.

\subsection{Phase 4: Global King Coordination}
\label{sec:king}

We introduce a reactive coordination layer that resolves inter-agent deadlocks without modifying any planning tree. The mechanism operates purely at the execution level.

\textbf{King selection.} Each agent has a priority value (configurable or random). The active agent with the highest priority is the King. When the King reaches its goal, the next-highest-priority active agent becomes King.

\textbf{King behavior.} The King follows its \smarttd{} path at full speed, ignoring all other agents in planning. On physical collision with another agent, the King initiates a \emph{chain push}: all agents along the push direction are displaced by one step. If the chain terminates at a wall, the first blocker is scattered sideways (perpendicular left, perpendicular right, or backward along its own path).

\textbf{Non-King behavior.} If within 5\,m of the King, a non-King agent actively \emph{flees}: it computes three candidate directions (away from King, perpendicular left, perpendicular right), selects the first that does not collide with a wall, and moves along it. Beyond 5\,m, non-King agents follow their own \smarttd{} paths normally, treating other agents as dynamic obstacles.

\textbf{Stuck detection.} If an agent makes no progress (< 2\,m movement) for 40 frames (2\,s), it triggers a rebuild. The King rebuilds ignoring all agents. Non-King agents rebuild with the King's position encoded as a 3\,m square wall obstacle, forcing the planner to route around the King's vicinity.

\textbf{Post-move overlap resolution (Phase 4.5).} Three passes over all agent pairs resolve any remaining overlaps: King--non-King overlaps push the non-King away; non-King--non-King overlaps push both apart equally. Wall checks prevent pushing agents into walls.

This mechanism is analogous to PIBT's priority inheritance in continuous space. PIBT agents backtrack by one grid cell; our agents flee along continuous vectors with the RRT* tree providing fallback global paths after displacement.

\textbf{Three decoupled movement layers.} The system combines three mechanisms that operate independently: (1)~the RRT* tree provides a global path via waypoint-following (pure pursuit); (2)~SMART incremental repair updates the path when walls or OHZs invalidate edges ($\sim$5\,ms); (3)~King/flee/push directly adjusts agent positions via vector arithmetic each frame, without touching the tree. After a King push displaces an agent, SMART replans in $\sim$5\,ms to provide a new global path. This layered design is why pushed agents move smoothly in continuous space rather than in discrete grid jumps.

\subsection{Phase 5: Shared Wall Discovery}

When agent $A$ discovers walls $\{w_1, \ldots, w_k\}$ in a frame, the central coordinator broadcasts them to all agents. Each receiving agent $B$ runs \texttt{update\_static\_obstacles()} against its own tree $\mathcal{T}_B$ for each new wall. This creates a cooperative exploration effect: agent $B$ may reroute \emph{before} encountering the wall physically, avoiding surprise blockages.

The alternative (independent mode) provides no inter-agent wall sharing. Each agent discovers walls only through its own LiDAR. Our ablation study (Section~\ref{sec:sharing_ablation}) quantifies the benefit.

\subsection{Metrics}

\begin{itemize}
    \item \textbf{Success rate}: fraction of trials where all agents reach their goals within the timeout.
    \item \textbf{All-done time}: simulation time when the last agent reaches its goal (median over 1{,}000 trials).
    \item \textbf{Rebuilds}: number of full RRT* rebuilds per trial (lower is better; incremental repair avoids these).
    \item \textbf{Inc.\ OK}: number of successful incremental repairs per trial.
    \item \textbf{Spread}: difference between the slowest and fastest agent's arrival time (lower indicates fairness).
\end{itemize}

\subsection{Configurations}

We compare five configurations:
\begin{itemize}
    \item \textbf{E3} (recommended): Lazy+Eager repair, shortcut smoothing (150 iters), detour detection ($\rho > 1.5$), wall-block check, LSR = 80\,m.
    \item \textbf{No Shortcut}: E3 without path smoothing.
    \item \textbf{No Detour}: E3 without detour-triggered rebuilds.
    \item \textbf{Baseline}: No shortcut, no detour, no wall-block check.
    \item \textbf{Senior}: Path-only repair (scan only path-adjacent edges).
\end{itemize}

All experiments run on an Intel Core i9-14900K with 64\,GB RAM. Each scenario$\times$configuration is evaluated over 1{,}000 independent trials with randomized pedestrian positions and agent tiebreakers.

\subsection{Spatial Index v2}
\label{sec:spatial_index}

The per-repair cost of E3 is dominated by scanning all $E$ edges against each new wall. We implemented a grid-bucket spatial index that partitions the workspace into 4\,m$\times$4\,m cells. Each edge is registered in the cells it passes through. When a new wall arrives, only edges in cells overlapping the wall's bounding box are checked.

A first attempt (v1) using heap-allocated \texttt{Vec} per query was \emph{slower} than linear scan, because 300 wall segments fit in 4.8\,KB (L1 cache); linear scan has perfect memory prefetch, and the per-call allocation overhead exceeds the savings. Spatial Index v2 eliminates all per-query allocation with a zero-copy design: allow duplicate wall checks (extra 5\,ns per duplicate is negligible) and use a single-cell fast path. On megacampus, wall-clock time drops from 66.1\,s to 48.6\,s ($-26$\%). Small maps are slightly slower due to HashMap overhead, but this is irrelevant since small maps complete in under 1\,s. The pruned edge set is identical to full scan: an edge geometrically distant from a wall cannot intersect it.

\section{Real Robot Deployment}
\label{sec:deployment}

We deployed the system on a physical robot navigating real indoor environments.

\textbf{Hardware.} A Raspberry Pi~5 (4-core, 2.4\,GHz) runs Cartographer SLAM and motor control as a thin client. An Alienware Aurora R16 (Intel i9-14900K, 24 cores, 64\,GB) serves as the central planner running \smarttd{} in Rust. Communication uses CycloneDDS over a WiFi access point ($10.42.0.0/24$, ROS\_DOMAIN\_ID=42).

\textbf{Why centralized.} Cartographer SLAM on the Pi~5 already consumes $\sim$1.5 CPU cores. RRT* with 15{,}000 iterations takes $\sim$300\,ms on Pi~5 vs.\ $\sim$40\,ms on i9 (7.5$\times$ slower). Running \smarttd{} on-board would leave insufficient headroom for SLAM.

\textbf{Sensing pipeline.} The Pi~5 streams LiDAR scans and SLAM-estimated pose to the i9. The i9 extracts walls from the occupancy grid, detects dynamic obstacles by comparing LiDAR points against known walls (points not near any wall are classified as dynamic, clustered, and tracked across frames for velocity estimation), and feeds all obstacle data to the Rust planner.

\textbf{Multi-agent extension.} The i9 planner supports multiple agents via the \texttt{car\_names} parameter. Each agent spawns an independent Rust \texttt{smart\_planner\_server} subprocess with per-agent \texttt{robot\_radius}. Other agents are encoded as dynamic obstacles with OHZ. A second robot (Yahboom M3 PRO, mecanum drive) has been integrated at the code level (\texttt{m3pro\_client.py}), pending full field testing.

\textbf{Key deployment findings:}
\begin{itemize}
    \item CycloneDDS required killing all Python3/RViz2 processes before WiFi reconnection to avoid lockups.
    \item Dynamic obstacle clustering required a minimum of 8 LiDAR points and 1.0\,s temporal persistence to suppress noise.
    \item The robot marker in RViz uses a CUBE (0.40$\times$0.35$\times$0.15\,m) matching the physical chassis.
\end{itemize}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\section{Discussion}

\textbf{Scalability.} Our system is tested with up to 8 agents. The per-frame cost scales as $O(N^2)$ for pairwise distance checks and $O(N \cdot E)$ for shared wall repair (each new wall triggers repair on all $N$ agents' trees with $E$ edges). For $N > 10$, the shared repair cost may become a bottleneck; the spatial index optimization reduces this to $O(N \cdot k)$ where $k \ll E$.

\textbf{Limitations.} The Global King system cannot resolve all deadlocks. Two non-King agents facing each other in a narrow corridor have no priority differentiation. Our mega\_hospital scenario shows 96--100\% success depending on configuration; the failures occur when two non-King agents deadlock in corridors too narrow for flee maneuvers. Extending priority inheritance to non-King pairs would address this at the cost of additional complexity.

\textbf{Comparison with MAPF.} Our system targets a fundamentally different operating regime: 2--8 physical robots in unknown, large-scale environments with continuous dynamics. Grid-based MAPF excels at 100+ agents on known graphs with discrete movement. The two approaches are complementary rather than competing.

\textbf{Future work.} (1) Spatial index for incremental repair using R-tree or grid-bucket to check only edges near a new wall's bounding box, reducing per-wall cost from $O(E)$ to $O(k)$. (2) On-board planning for robots with sufficient compute (e.g., Jetson Orin NX). (3) Time-aware coordination that predicts future agent positions rather than reacting frame-by-frame.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\section{Conclusion}

We presented a multi-agent navigation system that extends \smarttd{} to unknown environments with cooperative wall discovery and reactive coordination. The system achieves 100\% success rate on all large-scale scenarios with 4 agents, validated over 50{,}000+ benchmark trials. Key results: incremental wall repair provides $22.4\times$ speedup over full rebuild; shared wall discovery yields $1.04\times$--$2.09\times$ faster completion than independent exploration; the Global King coordination mechanism resolves deadlocks in 2\,m-wide corridors with 8 agents at 100\% success rate. The system has been deployed on a physical robot using ROS2 and a centralized planner architecture.

Our contributions are: \texttt{update\_static\_obstacles()} for permanent wall repair, the Lazy+Eager adaptive architecture, Spatial Index v2, Global King coordination, and the shared wall discovery mechanism.
